GPT-6 Luna Is Now Available on Modellix

September 24, 2026
OpenAI LLM API Model Launch
Modellix Team Official
Summary

GPT-6 Luna is live on Modellix as openai/gpt-6-luna. The cheapest GPT-6 tier costs $0.10 per million input tokens and is built for high-volume calls.

GPT-6 Luna is officially live on Modellix under the model ID openai/gpt-6-luna.

OpenAI shipped Luna alongside GPT-6 Sol on September 22, 2026. It is the low-cost, fast-response tier of the GPT-6 family, and you can call it today through the Modellix LLM gateway with the API key you already use.

If a large share of your traffic is classification, extraction, routing, or first-pass summaries, Luna is the model that changes your monthly bill.

What’s New in GPT-6 Luna

Built for volume

OpenAI positions Astra for the most demanding work and Sol for everyday difficult tasks. Luna is where the high-frequency calls go: the short, repetitive requests that would be wasteful on a frontier model.

$0.10 per million input tokens

OpenAI cut Luna’s API price by more than half against GPT-5.6 Luna: input drops from $0.20 to $0.10 per million tokens, and output from $1.20 to $0.50.

A real step up from GPT-5.6 Luna

On AutomationBench 1.0.6, Luna at high effort improves on GPT-5.6 Luna by 5.4 percentage points while costing 58% less per task. On DeepSWE 1.1, Luna at max effort scores 66.6%, which OpenAI reports as comparable to Claude Opus 5 and Fable 5 at medium effort, at 93% and 96% lower cost per task. These are OpenAI’s published figures, so check them on your own workload before you budget around them.

Factuality at a fraction of the cost

On OpenAI’s internal factuality evaluation, Luna at higher effort levels matches GPT-5.6 Sol at roughly a hundredth of its cost.

1.05M context, text and image in

On Modellix, Luna takes text or image input, returns text, and accepts up to 1.05M tokens of context. Inputs above 272K tokens are billed in a second Input Context tier.

What Can You Build with GPT-6 Luna

A natural fit is a support-ticket triage step: every incoming ticket goes to Luna with a fixed label set (billing, bug, feature request, other) and a one-word answer. Only the tickets that need a drafted reply move on to Sol. The triage call is short in and short out, which is the shape Luna is priced for.

We tested that step through the gateway on September 24, 2026, using openai/gpt-6-luna and the prompt in the request below. We wrote 12 tickets with known labels (four bugs, three billing questions, three feature requests, two general questions), including a few that could go either way, such as “My card was declined but the payment still shows as pending” and “Webhook retries stop after the first 500 error instead of backing off.” Luna matched all 12 labels and answered each one in five or six output tokens, with no extra explanation to strip.

Twelve hand-written tickets are a smoke test, not an accuracy rate. Before routing real traffic, run a few hundred tickets your team has already labeled and track agreement and cost per thousand tickets. If one label slips, tighten its definition in the prompt before you escalate that label to Sol.

What This Means for Modellix Users

With a three-tier family, the practical pattern is routing, not picking. Send bulk traffic to Luna, escalate the calls that need more reasoning to Sol, and reserve Astra for the work that justifies it. On Modellix that routing needs no extra integration: one key, one base URL, and per-call cost logs that show whether an escalation was worth it.

If you want to stay on the newest Luna release automatically, use the alias ~openai/gpt-luna-latest. For evaluations, pin the fixed ID openai/gpt-6-luna so a future release does not change what you are measuring. The API guide covers request paths and logs.
