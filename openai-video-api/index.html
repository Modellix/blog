OpenAI Video API Shutdown: What to Replace After Sora 2

August 19, 2026
AI Video API OpenAI Migration Guide
Modellix Team Official
Summary

OpenAI's Videos API and Sora 2 models reached their removal date on September 24, 2026. Here are the affected integration points and live routes to evaluate next.

As of September 24, 2026, OpenAI’s Videos API and Sora 2 models have reached their published removal date. OpenAI lists no replacement video model or endpoint. A code example that remains visible in the old video guide is not a basis for a new production integration.

If your application used Sora, identify every video job path, preserve outputs you need, and move generation to another provider. This guide maps the affected calls and four video routes currently published on Modellix. Those routes are alternatives to evaluate, not drop-in replacements for Sora.

Sora 2 shutdown explained: dates and affected IDs

OpenAI notified developers on March 24, 2026 that it would remove the entire Videos API and these model IDs on September 24:

  • sora-2 and sora-2-pro
  • sora-2-2025-10-06, sora-2-2025-12-08, and sora-2-pro-2025-10-06

The deprecations table leaves the replacement column empty. Pinning a dated snapshot does not avoid the shutdown. The separate Sora web and app experiences ended on April 26, 2026. OpenAI’s consumer content export at sora.chatgpt.com/sunset is for Sora content; it is not presented as an archive for API video jobs.

What existing Sora integrations need to replace

Existing dependency Migration consequence
POST /v1/videos, edits, extensions, and character uploads The Videos API family is on the removal list. Replace job creation and any feature-specific flow with a supported video route.
GET /v1/videos/{video_id}, /content, and job listing Do not rely on OpenAI video IDs as your media archive. Save any outputs you can still retrieve to storage you control.
video.completed and video.failed events, polling, and Batch jobs targeting /v1/videos Map status handling, callbacks, retry rules, and batch scheduling to the new provider’s task contract.
Hard-coded Sora aliases or snapshots Replace model selection and request parameters. Changing only the model string will not translate the rest of the request.

OpenAI published the removal date, not a universal HTTP error code or a guaranteed retrieval window for old jobs. Treat failed Sora calls as a migration signal rather than automatically retrying them. If an asset exists only in an OpenAI video job, check your account for any remaining retrieval access immediately.

Before switching production traffic, test representative prompts and, for image-to-video jobs, the same input image. Confirm the allowed duration and resolution, inspect the generated file, and compare the billed cost. Keep your application’s video job ID separate from the provider’s task ID so future model changes do not strand your records.

Can you still use an OpenAI API for video?

OpenAI’s published September 24 removal covers its Videos API and every listed Sora 2 alias and snapshot. Its deprecations page names no successor, and it does not identify the Responses API as a video migration path. OpenAI’s other APIs are separate products; a working image API does not keep Sora video generation available.

If you need video now, select a current video provider and adapt the request, task status, output storage, and billing checks. The four Modellix routes above give you concrete starting points; the Veo 3.1 API guide goes deeper on the submit, poll, and retrieve flow.
