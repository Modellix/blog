What Gemini 2.5 Flash Image is in September 2026

Gemini 2.5 Flash Image is Google’s native image generation and editing model — “Nano Banana” is the product name, gemini-2.5-flash-image is the API id. It went through a preview from May 2025, reached general availability on October 2, 2025, and was the model that made conversational, multi-turn image editing a mainstream API feature. Google’s official model card still describes it in the present tense: “our best engine for high-velocity visual creation,” best for high-volume generation, conversational image editing, and low-latency creative workflows.

The model card facts that matter for integration, read September 6, 2026:

  • Model code: exactly gemini-2.5-flash-image. The -preview variant was shut down January 15, 2026.
  • Inputs / outputs: image and text in, image and text out. No thinking mode, no function calling, no context caching, no search grounding — check the card’s capability list before you plan around those.
  • Token limits: 65,536 input tokens, 32,768 output tokens.
  • Output size: fixed ~1K band — 1024×1024 on 1:1, with ten aspect ratios (1:1, 2:3, 3:2, 3:4, 4:3, 4:5, 5:4, 9:16, 16:9, 21:9). There is no 2K/4K output mode; resolution tiers arrived with the Gemini 3 image models.
  • Batch API: supported, and the only discount route (more below). Flex and Priority inference are listed as not supported for this model.
  • Watermarking: every generated image carries a SynthID watermark.

Google now positions it inside the four-model “Nano Banana” line on the image generation guide: Nano Banana 2 Lite, Nano Banana 2, Nano Banana Pro — and Nano Banana (Gemini 2.5 Flash Image), “the legacy pioneer of the Nano Banana series.” Google’s own guide is explicit that the model is a workhorse you should plan to leave, which is the single most important fact most tutorials from earlier this year still miss.

Gemini 2.5 Flash Image API pricing, pulled today

The rates below come from Google’s Gemini API pricing page, fetched September 6, 2026. Image models bill per image, not per token, on output:

Service class Input (text/image) Output
Standard $0.30 per 1M tokens $0.039 per image
Batch API $0.15 per 1M tokens $0.0195 per image

How the per-image number works: image output is priced at $30 per 1M tokens, and any 1K-class image — whatever its aspect ratio — consumes 1,290 output tokens. 1,290 × $30/1M = $0.039. The pricing page also shows Flex and Priority columns ($0.0195 and $0.0702 per image), but the model card lists Flex and Priority inference as unsupported for this model, so treat Standard versus Batch as the real comparison.

A worked example: 10,000 images on Standard = $390. The same volume through the Batch API = $195, because batch halves both the input rate and the per-image output price. Input barely registers: 10,000 prompts of ~300 tokens each is 3M input tokens — $0.90 at the standard input rate. Text output (when the model returns commentary alongside an image) follows Gemini 2.5 Flash text pricing.

Two billing notes worth writing down: there is no free tier for this model on the current pricing page, and per-image pricing is flat — you cannot save by dropping resolution the way you can with the resolution-tiered Gemini 3 image models.

The shutdown: what October 2, 2026 means

Google announced in its July 2026 release notes that the entire Gemini 2.5 family would be retired in October 2026 — gemini-2.5-pro, gemini-2.5-flash, gemini-2.5-flash-lite, and gemini-2.5-flash-image. The deprecations page tracks the dates, and for the image model the entry is unambiguous:

  • gemini-2.5-flash-image — released October 2, 2025 — shutdown date October 2, 2026, the same date on both the Gemini Developer API and the enterprise platform, with no “unless you have a contract” carve-out listed.

Two nuances keep this honest. First, Google frames deprecation dates as the earliest retirement — “may move later, but not earlier” is how independent trackers read it — so October 2 is the planning date, not a guarantee of exactly-then. Second, the deprecations table’s own “recommended replacement” column still names gemini-3.1-flash-image-preview, which is stale: that preview model was itself shut down on June 25, 2026. The live GA successor you actually migrate to is gemini-3.1-flash-image (Nano Banana 2, GA since May 28, 2026, no shutdown date announced). Google’s image generation guide makes the same point in product terms when it recommends moving to Nano Banana 2 — or Nano Banana 2 Lite if cost is the driver.

What changes on the day: a request using a shut-down model name returns a 404-style “model not found” error. Nothing else about your pipeline breaks — you swap the model string and re-test, which is the whole migration story in section seven.

Getting an API key, and which endpoint to call

Keys for the Gemini API come from Google AI Studio: sign in, open Get API key, and create a key — the API key guide walks through it. There is no separate key type for image models; the same key that calls Gemini text models calls gemini-2.5-flash-image.

One decision you need to make before writing code is which request surface to use, because Google’s image documentation has split in two:

  • generateContent — the classic stateless endpoint (POST /v1beta/models/{model}:generateContent). Google now labels it “legacy,” but it remains fully supported, and it is the surface the model shipped with. Google keeps a dedicated legacy image generation page that documents gemini-2.5-flash-image explicitly — this is the path for existing integrations and for this article’s code.
  • Interactions API — Google’s newer conversational surface, generally available since June 2026, and what the current image generation guide leads with. Its supported image models are the Gemini 3 line (gemini-3-pro-image and gemini-3.1-flash-image); the docs examples all target those, and gemini-2.5-flash-image is not listed there. For 2.5, the documented call surface is generateContent.

If you are building fresh, follow Google’s direction of travel and use the Interactions API with gemini-3.1-flash-image. If you are maintaining a call that already works on 2.5, keep generateContent — the code below — and plan the string swap.

Errors, limits, and the gotchas nobody pages warn about

Four failure modes cover almost everything you will hit:

  • 404 NOT_FOUND / model-not-found — after October 2, 2026 this is what every call returns; before that date it usually means a typo (gemini-2.5-flash-image is case-sensitive) or a region/endpoint mismatch.
  • 400 INVALID_ARGUMENT — malformed response_format (for example, sending image_size to this model) or an unsupported MIME type on input images (png, jpeg, webp, heic, heif are supported).
  • 429 RESOURCE_EXHAUSTED — rate limit. Back off with exponential delay and retry; batch workloads should use the Batch API instead of hammering the online endpoint.
  • Safety blocks — refusal responses and aggressive filtering on realistic human content were the model’s known weak spots since launch; budget prompts accordingly.

And four gotchas that cost real time:

  1. Feature freeze is already in effect. Everything interesting Google has added to image generation since — thinking mode, search grounding, 4K output, video-to-image, up to 14 reference images — landed on the Gemini 3 image models, not on 2.5. If your roadmap needs any of those, 2.5 is a dead end by design, not by accident.
  2. The docs have quietly demoted it. The current image generation guide’s model list calls it the “legacy pioneer,” and the deprecations table’s replacement column is itself out of date (it points at a preview that shut down in June). Read both pages through that lens before copy-pasting model ids from them.
  3. No free tier. The watermark-free free experimentation period ran through the -preview endpoint, which shut down January 15, 2026. The pricing page lists “Free Tier: Not available” for this model today.
  4. Budget for migration in the price. At $0.039/image standard, 2.5 is not cheaper than its successors for most jobs — the cost argument cuts the other way, toward Nano Banana 2 Lite.

Which model should you call instead?

The migration is a three-step change, not a rewrite:

  1. Swap the model string: gemini-2.5-flash-image → gemini-3.1-flash-image (the GA successor). If you need the absolute cheapest output, evaluate gemini-3.1-flash-lite-image (Nano Banana 2 Lite), which Google’s guide explicitly suggests for 2.5 users trading up on cost.
  2. Add image_size only if you want it: on the Gemini 3 image models, response_format accepts 512 / 1K / 2K / 4K. Leaving it off keeps 1K output and the closest behavior parity with 2.5.
  3. Regression-test the things that matter for your workload: character consistency across edits, text rendering inside images, and prompt-adherence on your own prompt corpus. Outputs are not pixel-identical between generations, so re-baseline your quality checks rather than diffing against old images.

When 2.5 still makes sense: you are inside the October window and cannot touch the pipeline, your prompts are tuned against its exact quirks, or you are explicitly holding for a legacy client. When it does not: any new build, anything needing 2K/4K or search-grounded images, anything with a roadmap past October. One scope note on the alternatives: if your Gemini usage has historically run through Vertex AI (enterprise deployments) or you are migrating off the retired Imagen 4 endpoints (shut down August 17, 2026 on the Gemini API), the same successor applies — Google maps Imagen 4 standard/fast to gemini-3.1-flash-image and Imagen 4 ultra to gemini-3-pro-image, so the Gemini 3 image family is the common landing spot. Frequently Asked Questions

Does Gemini 2.5 Flash Image still have an API?

Yes, as of September 6, 2026. The model id gemini-2.5-flash-image is live and stable on the Gemini API, documented on its official model card, and callable through the generateContent surface it shipped with (the newer Interactions API lists only the Gemini 3 image models). It carries a scheduled shutdown date of October 2, 2026.

Is Gemini 2.5 Flash Image the same as Nano Banana?

Yes. Nano Banana is the product name for Google’s Gemini 2.5 Flash Image model; gemini-2.5-flash-image is its API id. “Nano Banana” is also now a four-model family name — Nano Banana 2 (Gemini 3.1 Flash Image), Nano Banana Pro (Gemini 3 Pro Image), and Nano Banana 2 Lite are its successors.

How much does the Gemini 2.5 Flash Image API cost?

On Google’s standard tier, $0.039 per image plus $0.30 per 1M input tokens (text or image), per the pricing page fetched September 6, 2026. The Batch API halves both to $0.0195 per image and $0.15 per 1M input tokens. There is no free tier.

How do I get a Gemini 2.5 Flash Image API key?

Create a key in Google AI Studio under Get API key. The same key works for image and text models — there is no image-specific key type.

What happens when Gemini 2.5 Flash Image shuts down?

Requests to the model return a not-found error, and the endpoint goes away for good. Google’s deprecations page lists October 2, 2026 as the shutdown date. Migrate by swapping the model string to gemini-3.1-flash-image and re-testing your prompts.

Can I call it through Modellix?

The literal /models/google/gemini-2.5-flash-image page no longer resolves — it renders “Model Not Found.” Modellix serves Google’s image models under the Nano Banana family names: google/nano-banana at $0.0351 per image (page linked above), with google/nano-banana-2 (Gemini 3.1 Flash Image) as the family’s routing default.

Gemini model status and pricing reflect public Google documentation as of September 6, 2026, and change frequently — the shutdown date is a deprecation schedule that Google can move, and Modellix list prices are our own sheet, not Google’s.
