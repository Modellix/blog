GPT-6 Luna Is Now Available on Modellix

September 24, 2026
OpenAI LLM API Model Launch
Modellix Team Official
Summary

GPT-6 Luna is available as openai/gpt-6-luna. Use the same Modellix API key for the GPT-6 family, send routine high-volume requests to Luna, and escalate only the exceptions.

GPT-6 Luna is officially live on Modellix under the model ID openai/gpt-6-luna.

OpenAI shipped Luna alongside GPT-6 Sol on September 22, 2026. It is the low-cost, fast-response tier of the GPT-6 family. Call it through the Modellix LLM gateway with one Modellix API key, then change the model ID to compare it with Sol or Astra.

If a large share of your traffic is classification, extraction, routing, or first-pass summaries, Luna is the model that changes your monthly bill.

What’s New in GPT-6 Luna

Built for volume

OpenAI positions Astra for the most demanding work and Sol for everyday difficult tasks. Luna is where the high-frequency calls go: the short, repetitive requests that would be wasteful on a frontier model.

$0.10 per million input tokens

OpenAI cut Luna’s API price by more than half against GPT-5.6 Luna: input drops from $0.20 to $0.10 per million tokens, and output from $1.20 to $0.50.

A real step up from GPT-5.6 Luna

On AutomationBench 1.0.6, Luna at high effort improves on GPT-5.6 Luna by 5.4 percentage points while costing 58% less per task. On DeepSWE 1.1, Luna at max effort scores 66.6%, which OpenAI reports as comparable to Claude Opus 5 and Fable 5 at medium effort, at 93% and 96% lower cost per task. These are OpenAI’s published figures, so check them on your own workload before you budget around them.

Factuality at a fraction of the cost

On OpenAI’s internal factuality evaluation, Luna at higher effort levels matches GPT-5.6 Sol at roughly a hundredth of its cost.

1.05M context, text and image in

On Modellix, Luna takes text or image input, returns text, and accepts up to 1.05M tokens of context. Inputs above 272K tokens are billed in a second Input Context tier.

What Can You Build with GPT-6 Luna

A support inbox could use Luna as a first-pass routing step. It labels incoming tickets as billing, bug, feature request, or other, so the helpdesk can place each case in the right queue without asking a larger model to draft a full reply first. The application applies the label; uncertain or high-risk cases can go to a person or to Sol for a fuller response.

We tested that step through the gateway using openai/gpt-6-luna and the prompt in the request below. We wrote 12 tickets with known labels (four bugs, three billing questions, three feature requests, two general questions), including a few that could go either way, such as “My card was declined but the payment still shows as pending” and “Webhook retries stop after the first 500 error instead of backing off.” Luna matched all 12 labels and answered each one in five or six output tokens, with no extra explanation to strip.

Twelve hand-written tickets are a smoke test, not an accuracy rate. Before routing real traffic, run a few hundred tickets your team has already labeled and track agreement and cost per thousand tickets. If one label slips, tighten its definition in the prompt before you escalate that label to Sol.

Switch Between Luna, Sol, and Astra with One API Key

Point your OpenAI-compatible app to https://llm.modellix.ai/v1 and add one Modellix API key. Send routine support tickets to openai/gpt-6-luna, move unclear cases to Sol, and reserve Astra for the hardest requests. Test all three on the same ticket queue without switching credentials, then choose the mix that fits your quality and cost targets.

Turn common ticket themes into help-center visuals with GPT Image 2 using the same Modellix key. Image and video jobs run through a separate media API and finish asynchronously; GPT-6 text calls stay on the synchronous LLM gateway.
